# Тестирование и калибровка Day Summary

Руководство по тестированию и калибровке AI-генерируемой сводки для `/day_stats`.

## Запуск тестов

### Unit и Integration тесты

Запустить все тесты для day_summary:

```bash
pytest tests/test_day_summary.py -v
```

Запустить конкретную категорию тестов:

```bash
# Тесты агрегации данных
pytest tests/test_day_summary.py::TestAggregateVideosData -v

# Тесты промпта
pytest tests/test_day_summary.py::TestBuildSummaryPrompt -v

# Тесты парсинга
pytest tests/test_day_summary.py::TestParseSummaryResponse -v

# Integration тесты
pytest tests/test_day_summary.py::TestGenerateDaySummary -v
```

### Тестирование на разных сценариях

Используйте скрипт `scripts/test_day_summary_scenarios.py` для тестирования с реальными данными:

```bash
# Тест на смешанных данных (по умолчанию)
python scripts/test_day_summary_scenarios.py

# Тест конкретного сценария
python scripts/test_day_summary_scenarios.py --scenario all_scale
python scripts/test_day_summary_scenarios.py --scenario mixed
python scripts/test_day_summary_scenarios.py --scenario few_videos

# Тест всех сценариев
python scripts/test_day_summary_scenarios.py --scenario all
```

## Доступные сценарии

| Сценарий | Описание | Use Case |
|----------|----------|----------|
| `all_scale` | Все видео с вердиктом SCALE | День успеха, все ролики зашли |
| `all_kill` | Все видео с вердиктом KILL | Провальный день, нужна мотивация |
| `mixed` | Смешанные результаты | Обычный день с разными результатами |
| `few_videos` | Мало видео (2-3) | Низкая активность |
| `many_videos` | Много видео (20+) | Высокая продуктивность |
| `short_hooks_win` | Короткие хуки побеждают | Паттерн: короткие хуки работают лучше |
| `long_hooks_fail` | Длинные хуки проваливаются | Паттерн: длинные хуки не работают |

## Калибровка промпта

### Проблемы и решения

#### 1. Summary слишком общий, без конкретики

**Проблема:** AI возвращает общие фразы без цифр и конкретных примеров.

**Решение:**
- Добавить в промпт требование использовать конкретные числа
- Привести примеры хороших ответов в промпте
- Увеличить `temperature` для более креативных ответов

#### 2. Summary слишком длинный

**Проблема:** AI генерирует слишком много текста, превышает лимит Telegram.

**Решение:**
- Уменьшить `DAY_SUMMARY_MAX_TOKENS` в `.env` (текущее значение: 500)
- Добавить в промпт явное требование краткости
- Ограничить количество bullet points в рекомендациях

#### 3. AI не замечает важные паттерны

**Проблема:** AI не выявляет корреляции между hook_type и успехом.

**Решение:**
- Улучшить форматирование данных в промпте
- Добавить explict инструкции искать корреляции
- Попробовать `reasoning.effort: high` для более глубокого анализа

#### 4. Summary не на русском языке

**Проблема:** AI отвечает на английском, несмотря на инструкции.

**Решение:**
- Усилить требование русского языка в system prompt
- Добавить примеры на русском языке
- Убедиться что модель поддерживает русский (Gemini 3 поддерживает)

### Как изменить промпт

Промпт находится в функции `_build_summary_prompt` в файле `src/ai/day_summary.py`.

**Основные секции промпта:**

1. **System context** - роль AI (Senior Growth Analyst)
2. **Данные** - агрегированная статистика
3. **Формат ответа** - структура с секциями
4. **Инструкции** - требования к стилю и содержанию

**Пример изменения для увеличения конкретики:**

```python
# Добавить в конец промпта
"""
ПРИМЕРЫ ХОРОШИХ РЕКОМЕНДАЦИЙ:
✅ "Делай больше видео с короткими хуками — сегодня они показали +35% к retention"
✅ "Тестируй варианты хука из топ-2 видео на новом контенте"

❌ "Улучшай хуки"
❌ "Работай над retention"
"""
```

### Настройки в config

Файл: `src/config.py` и `.env`

```env
# Включить/выключить AI summary
ENABLE_DAY_SUMMARY=true

# Максимальное количество токенов в ответе (100-1000)
DAY_SUMMARY_MAX_TOKENS=500

# Temperature для генерации (0.0-2.0, default: 0.7)
# Ниже = более предсказуемо, выше = более креативно
DAY_SUMMARY_TEMPERATURE=0.7
```

## Тестирование с реальными данными

### Подготовка тестовых данных

1. Загрузите несколько видео в бота
2. Дождитесь анализа
3. Запустите `/day_stats` чтобы увидеть summary

### Проверка качества summary

Хороший summary должен:

- ✅ Содержать конкретные цифры из данных
- ✅ Выявлять паттерны (например, корреляцию hook_type и score)
- ✅ Давать actionable рекомендации
- ✅ Быть кратким (не более 10-15 строк)
- ✅ Соответствовать выбранному формату с секциями

Плохой summary:

- ❌ Общие фразы без цифр ("Работай над хуками")
- ❌ Повторяет данные из статистики без анализа
- ❌ Слишком длинный (более 20 строк)
- ❌ Не дает конкретных рекомендаций

## Мониторинг качества AI

### Логи

AI pipeline логирует качество каждые N запросов (настройка `AI_QUALITY_LOG_EVERY_N`):

```
AI quality snapshot: {
  "total_calls": 25,
  "success_rate_pct": 96.0,
  "avg_latency_ms": 1234.5,
  ...
}
```

### Метрики для отслеживания

1. **Success rate** - процент успешных генераций
2. **Average latency** - среднее время генерации
3. **Cache hit rate** - процент запросов из кэша
4. **Parse failures** - количество ошибок парсинга

## Оптимизация стоимости

### Кэширование

Summary кэшируется на 1 час для одного и того же набора видео.

**Параметры кэширования:**

```python
# В generate_day_summary()
cache_ttl_sec=3600  # 1 час по умолчанию
```

### Минимальное количество видео

Summary генерируется только если видео >= 3:

```python
# В generate_day_summary()
min_videos=3  # Минимум 3 видео для анализа
```

### Reasoning effort

Для summary используется `reasoning.effort: medium` для баланса качества и скорости:

```python
# В _call_openrouter_for_summary()
if "gemini-3" in model_name.lower():
    payload["reasoning"] = {"effort": "medium"}
```

## Troubleshooting

### Summary не генерируется

**Возможные причины:**

1. **Недостаточно видео** - меньше min_videos (3 по умолчанию)
   - Решение: загрузите больше видео или уменьшите min_videos

2. **ENABLE_DAY_SUMMARY=false**
   - Решение: установите `ENABLE_DAY_SUMMARY=true` в `.env`

3. **Ошибка OpenRouter API**
   - Проверьте логи: `logger.warning("Failed to generate AI summary: ...")`
   - Проверьте API key в `.env`
   - Проверьте баланс OpenRouter

4. **Timeout**
   - Увеличьте timeout в вызове: `timeout=60.0`

### Summary некачественный

1. **Измените промпт** в `_build_summary_prompt()`
2. **Увеличьте temperature** для более креативных ответов
3. **Увеличьте max_tokens** если summary обрезается
4. **Попробуйте другую модель** в config

### Высокая стоимость API

1. **Проверьте кэш** - логи должны показывать "Returning cached day summary"
2. **Увеличьте cache_ttl_sec** до 2-3 часов
3. **Используйте min_videos=5** чтобы реже генерировать summary
4. **Уменьшите max_tokens** до 300-400

## Best Practices

1. **Тестируйте изменения промпта** на всех сценариях перед деплоем
2. **Мониторьте качество** через логи и метрики
3. **Собирайте фидбек** от пользователей о полезности summary
4. **Итерируйте промпт** на основе реальных кейсов
5. **Балансируйте** между качеством и стоимостью
